# 坦克大战首版验收报告

> 本文为早期 PVP 实现记录。当前 `/game` 为菜单，`/game/single` 为单人 PVE，`/game/online` 已接入双人合作 PVE。请以 [菜单与合作验收报告](tank-menu-online-report.md) 为当前验收依据。

日期：2026-11-18。目标：两个账号可以在博客内完成创建房间、开局、移动、射击、结算和重开。真实双浏览器操作由用户验收。

## 入口和操作

- 联机入口：`http://localhost:5173/game/online`（前端端口以 Vite 实际输出为准）。
- 两个独立浏览器环境登录不同账号；同一浏览器两个普通窗口共享登录 Cookie，不能作为独立账号环境。
- A 创建房间，B 输入房间号加入，双方准备后由房主开始。
- 点击画布获得焦点，WASD 或方向键移动，按住空格持续射击，松开停止射击。
- 自己的坦克用绿色标记，对手用黄色标记；两边显示各自血量和同一战局结果。
- 房主在结算后选择再来一局，双方重新准备并开始。

## 已实现范围

| 功能 | 行为 |
| --- | --- |
| 房间 | 双人上限、成员同步、准备/取消、主动退出、房主转移、空房回收 |
| 开局 | 本局独立 matchId、地图副本、双方加载完成才开始；加载超时返回等待 |
| 地图 | 原地图太小时使用内置 30列×20行、每格24px 的双人训练场；数据库原图和 HTTP 地图接口保持原样 |
| 移动 | 服务端固定50ms步长、120px/s；边界、砖墙、钢墙、河流与另一辆坦克阻挡 |
| 射击 | 服务端开火冷却350ms、子弹360px/s、每人最多4颗在场子弹；客户端只提交按键状态 |
| 命中 | 子弹沿移动路径检查最近障碍/坦克；不击中自己；每次命中扣1血 |
| 材质 | 砖墙被击毁后可通行；钢墙挡子弹且不被破坏；河流挡坦克但不挡子弹；树林与冰面可通过 |
| 结算 | 每人3血，归零判负；同一步双方死亡为平局；180秒未分胜负为平局 |
| 退出 | 对局中主动退出按认输处理，剩余房间返回等待；结算后退出不重复结算 |
| 重开 | 房主从结算返回等待，新局重新生成地图副本、血量、子弹和输入 |
| 同步 | 服务端约10次/秒广播；前端显示权威位置、血量、子弹与墙体变化；用版本/局号/帧号拒绝旧消息 |
| 清理 | 失焦、隐藏、断连和页面卸载清空按键；输入500ms未刷新后停止移动和开火 |

## 本次关键代码

- `game/engine/GameMovementEngine.java`：坦克移动与路径碰撞。
- `game/engine/GameCombatEngine.java`：开火、子弹、命中、伤害与胜负。
- `game/engine/GameArenaMapFactory.java`：联机训练场，保留正常大小的数据库地图。
- `game/runtime/GameMatch.java`：本局坦克、输入、子弹、已破坏墙体与最终结果。
- `service/game/GameRoomService.java`：房间状态、固定步长推进、结算和重开。
- `service/game/GameMatchService.java`：锁外地图查询、定时调用和发送编排。
- `controller/GamePlayController.java`：开局、加载、输入、恢复与重开消息入口。
- `frontend/src/views/GameView.vue`：房间、输入发送、血量与结算界面。
- `frontend/src/components/GameBattleCanvas.vue`：地图缓存、坦克/子弹绘制和键盘监听。
- `frontend/src/game/network/protocol.ts`：消息字段校验和类型。

新增输入字段 `fireHeld`，默认false兼容旧移动请求；新增 `/app/room/rematch`，正文为 `{"roomId":"当前房间号"}`。房间增加 FINISHED 状态；最终结果保留到重开或退出。game:state 增加 hp、bullets、destroyedCells、winnerUserId、endReason；game:end 增加 winnerUserId。前后端已同步契约。

房间/战局仍在内存中，状态变化由房间服务同步方法串行处理，地图读取及网络发送在锁外。本次不增加数据库表、依赖或新的基础设施，不修改开发数据。
