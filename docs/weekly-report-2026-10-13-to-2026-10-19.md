# 最近一周开发报告

**统计周期：2026 年 10 月 13 日—10 月 19 日（最近 7 个自然日，Asia/Hong_Kong）**

**项目：MyBlog 博客系统与联机坦克大战模块**

本报告根据统计周期内的 Git 提交、本次开发协作记录和当前工作区代码整理。周期内共有 8 次 Git 提交；坦克模块包含尚未提交的工作区改动，其具体开发日期不根据 Git 提交时间推断。

## 一、本周工作概述

本周完成了博客已有代码的版本管理整理，推进后端分层、富文本编辑与展示，并补齐 Docker、前端构建和 Nginx 部署配置及操作文档。

同时，启动博客内的联机坦克大战开发，完成素材整理、数据库地图读取、Canvas 场景绘制、玩家方向显示、持续绘制和键盘输入状态管理。目前已具备画面与输入基础，WebSocket、房间管理、服务端移动计算及战斗流程尚待实现。

## 二、本周主要成果

### 1. 博客基础与后端结构

- 将已有 Vue 3、TypeScript、Spring Boot、MySQL 博客代码纳入 Git 管理，整理前后端目录、本地启动和构建说明。
- 对文章、用户、分类相关后端代码进行分层，明确 Controller、Service、Repository 的职责。
- 增加请求与响应 DTO、参数校验、业务异常与统一异常处理。
- 使用 `CurrentUserService` 集中处理 Session 登录身份读取、登录建立、退出和账号有效性检查。
- 将文章操作权限放入业务服务，保留作者与管理员的操作边界。
- 补充后端开发规范文档，明确后续新增功能的实现与验证流程。

现有注册、登录、文章管理等基础能力作为本周整理的项目基线记录；首次入库不等同于这些功能全部在本周从零开发。

### 2. 富文本编辑与文章展示

- 接入 Tiptap 编辑器，支持标题、加粗、斜体、列表、引用、代码块、撤销与重做等操作。
- 增加代码语言选择、语法高亮和代码复制功能。
- 为文章阅读页生成标题目录，统一编辑与阅读样式。
- 使用 DOMPurify 和 Jsoup 分别清理前端、后端 HTML 内容。
- 增加 `TEXT`、`HTML` 正文格式区分，兼容已有纯文本文章，并提供格式字段迁移脚本。

### 3. 部署配置与操作文档

- 增加 Spring Boot 后端 Dockerfile、Compose 配置及环境变量示例。
- 根据服务器构建条件调整基础镜像来源和 Maven 构建网络配置。
- 增加前端构建脚本，配置构建时的内存限制。
- 增加 Nginx 静态页面、Vue 路由回退与 `/api/` 反向代理配置。
- 整理容器构建、启动、更新、日志查看和公网访问检查步骤。

当前文档描述的部署结构为：Nginx 提供前端并代理 API，后端运行于容器，MySQL 使用宿主机已有数据库。本次报告核对了配置和已有部署记录，未重新验证服务器在线状态；游戏 WebSocket 的生产部署仍待后续开发。

### 4. 坦克游戏规划与素材管理

- 编写模块职责规划与分步实施文档，确定在现有博客前后端内逐步接入游戏。
- 完成 116 件素材的分类：两套图片素材分别为 53 件、51 件，音频为 12 件。
- 将素材迁入 `frontend/public/resources`，按玩家、敌人、地形、子弹、特效、界面和音频等用途管理。
- 保留素材目录和路径、大小、SHA-256 清单，便于追溯。
- 使用 `assets.ts` 集中维护素材地址，通过 Vite 的 `BASE_URL` 处理资源基础路径。

### 5. 数据库地图与查询接口

- 复用现有 `myblog` 数据库，通过 `game_map` 保存地图名称、格子尺寸和二维 JSON 地图种子。
- 使用整数表示空地、砖墙、钢墙、河流、树林和冰面等材质。
- 按 Entity、Repository、Service、DTO、Controller 分层实现地图查询。
- 提供 `GET /api/game/maps/{id}`，由前端获取地图初始布局。
- 编写地图加载器，遍历二维矩阵并按材质编号绘制图片。

目前使用材质测试地图验证加载链路，正式对战地图与双方出生点仍需确定。

### 6. Canvas 场景与玩家绘制

- 添加 `/game` 路由和 `GameView.vue`，设置 960 × 624 的黑色画布。
- 支持按地图返回的格子尺寸绘制地形，当前测试采用 24 像素格子。
- 使用离屏 Canvas 缓存地图，逐帧绘制时复制缓存背景，减少重复遍历地形。
- 将玩家绘制拆到 `playRenderer.ts`，加载并解码坦克精灵图，按方向裁剪显示。
- 接入原生 `requestAnimationFrame` 持续绘制，按顺序清屏、绘制背景、绘制玩家。
- 在离开页面时取消动画请求并释放输入监听，保留异步初始化完成后的卸载检查。

当前绘制频率跟随浏览器刷新节奏，没有设置固定 60 FPS 上限，也没有进行帧率或性能基准测量。

### 7. 键盘输入状态管理

- 支持方向键和 WASD，统一使用 `0～3` 表示方向、`null` 表示停止输入。
- 忽略长按重复事件，仅在输入方向变化时通知页面。
- 支持多键同时按下时最后按键优先，松开后回退到仍按住的方向。
- 正确处理 W 与向上键等同方向按键组合。
- 在画布或窗口失焦时清空输入，卸载时解除监听并报告停止。
- 页面收到停止输入时保留坦克朝向，避免把 `null` 传给绘制器。

目前输入回调用于本地转向和控制台验证，尚未向服务器发送消息；坦克位置仍为初始化坐标。

## 三、技术问题处理与方案确定

| 问题或决策 | 本周处理结果 | 后续关注 |
| --- | --- | --- |
| 素材路径导致画面无法正常显示 | 统一资源配置，改用正确的基础路径引用素材 | 部署后验证实际资源路径 |
| `GameMap` 编译产物出现无效构造方法字节码 | 清理重编译后恢复运行，在实体中显式声明无参构造方法作为绕过措施 | 编译链反复生成异常字节码的根因尚未确认 |
| 重绘依赖按键事件 | 改为持续绘制循环，输入回调只更新状态 | 接入服务器状态后继续保持绘制与规则计算分开 |
| 松键、多键与失焦状态处理 | 增加按键列表、停止输入和监听清理 | 联机时补充断线后的服务端输入清理 |
| 联机计算职责 | 确定由服务端计算移动、碰撞、伤害和胜负，浏览器采集输入并绘制 | 权威战局、游戏循环和状态同步尚待实现 |

另外，阅读参考坦克项目，梳理了定时器更新、模型集合管理和多 Canvas 图层结构；识别到绘制函数夹带移动计算、全局监听清理不足等问题，明确当前项目后续应分别维护游戏计算与画面绘制。

## 六、后续开发计划

1. **定义最小通信协议**：明确输入、玩家状态、消息类型、输入序号和服务端时间或帧号。
2. **建立 WebSocket 连接**：完成前端连接模块、后端接入、消息校验及断开清理。
3. **跑通服务端移动与同步**：服务端保存输入并计算位置，广播状态，前端根据状态绘制。
4. **完善双人房间流程**：创建、加入、准备、开始和退出，明确本局地图与出生位置。
5. **逐步补齐战斗与异常处理**：射击、碰撞、伤害、结算，以及掉线和重连。

下一阶段优先验收目标：两个浏览器进入同一个测试战局，通过按下和松开方向键驱动服务器计算移动，双方能够看到一致的位置与停止状态。
